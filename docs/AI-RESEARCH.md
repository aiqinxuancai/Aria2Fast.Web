# 番剧调查与评析

在「设置中心 → AI 与智能功能」配置 AI 接口，以及至少一种搜索服务的 API Key：Brave Search、Serper、SerpApi 或 Tavily。模型可选择服务；默认依次尝试 Brave、Serper、SerpApi、Tavily，遇到错误或空结果自动回退到其他已配置服务。各服务均使用网页搜索，适合调查作品、原作、出版社与制作团队。

番剧详情的「调查并评析」会核对作品身份，调查原作与改编信息，整理作品概况、原作信息、动画与改编、综合评析、观看建议以及待核实事项。来源以编号和可点击链接显示。推荐分是 AI 的主观判断，不是 TMDB 或其他网站评分；没有取得外部证据时不评分。没有配置搜索服务时仍可生成基于简介的有限总结，并明确标记未检索。

调查采用模型决定下一步、执行工具、将结果反馈给模型的循环，而非固定搜索词拼接。现有四种 AI 协议均通过 JSON 动作使用同一套工具：

- `search`：`query` 加可选的 `provider`（`auto`、`brave`、`serper`、`serpapi`、`tavily`）。每次最多五项结果，摘录最多两千字符，重复 URL 共用来源编号。
- `fetch`：`url`。读取网页正文，反馈最终地址、HTTP 状态、截断标记与来源编号，用于核实搜索摘要。
- `finish`：输出结构化调查总结；校验必填内容、评分范围和来源编号后保存。格式或引用有误时反馈给模型修正。

一次调查最多六次搜索、四次网页抓取、十六轮模型调用，总时限八分钟。搜索失败和抓取失败作为工具观察反馈给模型；取消请求会传递到模型和网络调用。同一番剧的并发请求在服务内合并复用成功结果，避免同时重复生成。网页资料只作为不可信证据传入提示，不允许覆盖系统指令。引用编号校验不能保证模型事实判断完全正确，重要结论仍应核对所附来源。

## 持久化

完成的评析及来源、查询记录、生成时间、模型名称写入数据目录的 `state.json`，与简介翻译一起持久化。评析按番剧 ID 保存，无七天过期限制，切换或删除 AI 配置后仍可读取。旧版按模型保存的评析也能继续读取，优先使用最近一份。

「重新调查」使用当前配置生成新结果，只有完整成功后才覆盖旧版；失败时保留已保存的内容。服务器重启会保留完成的结果，但不会恢复进行中的调查。详情页先显示番剧信息，再触发自动评析和翻译；调查过程中可查看其他内容。

## 页面抓取范围

参考 `QQRebotPlugin/MiraiAngelaAI/Service/WebFetchService.cs` 的 HTTP 实现：只允许公网 HTTP/HTTPS，重定向逐次校验，连接绑定已校验的 DNS 地址，禁止访问回环、内网与云实例元数据地址。最多五次重定向、二十秒、1 MiB 响应；移除脚本和样式，提供最多一万字符正文并标记截断。

抓取无需搜索密钥，直接连接公网，不使用应用的代理、Cookie 或登录态。当前只支持静态 HTML/文本，不执行 JavaScript，不读取 PDF；依赖脚本、登录或反爬验证的页面可能无法取得正文。搜索与 AI 请求继续使用应用代理设置。

## 验证

`dotnet run --project tests/Aria2Fast.Web.Tests -c Release` 覆盖调查循环、按结果追问、抓取、引用校验、预算、取消、四个搜索服务请求格式及回退、抓取地址限制和持久化。

`python tests/integration.py` 使用本地 AI fixtures 验证四种协议的评析生成、缓存读取与刷新失败保留。`node tests/browser/smoke.cjs` 验证调查按钮状态、分项内容、安全来源链接和错误后的旧评析展示。搜索 API 使用模拟响应测试，不消耗真实密钥额度。
