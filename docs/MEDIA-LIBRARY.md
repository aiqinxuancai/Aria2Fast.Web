# 媒体库

> **实施状态（2026-11-26）**：第一阶段（数据打通）已完成，包括扫描、作品与集数识别、Bangumi / TMDB 资料获取、海报缓存、下载完成自动入库和接口。海报墙页面与播放器属于第二阶段，尚未开始。

媒体库把本地下载目录中的视频按作品整理，并获取海报、简介、评分和分集标题。它只读取文件，不移动、不改名；和订阅打通后，从「发现番剧」订阅的作品可以精确关联到 Bangumi 条目。

在「设置中心 → 媒体库」可以开关媒体库和资料获取、设置定时扫描间隔、修改 Bangumi API 地址（可填镜像），以及立即扫描。

## 什么时候扫描

- 程序启动约 5 秒后扫描一次，之后按设置的间隔（默认 60 分钟）定时扫描。
- 本应用提交到**本地节点**的任务下载完成后自动扫描；同一批完成的文件合并为一次扫描。
- 在设置页点「立即扫描」，或调用 `POST /api/library/scan`。

扫描只遍历文件，速度很快；新作品的资料在后台逐个获取，每个之间间隔 1 秒。

## 作品如何划分

媒体库中的一个「作品」对应一季，也就是 Bangumi 的一个条目，通常也对应一条订阅。每个视频按下面的顺序归入作品：

1. **本地订阅的作品目录**：视频位于某条本地订阅的「下载目录 / 作品目录」下，就属于这条订阅。从「发现番剧」订阅时作品目录会自动填写。没有作品目录的订阅，只有在下载目录不与其他订阅共用时才认领该目录，避免把手动建立的「Anime」之类合集目录当成一部作品。
2. **下载目录下的第一级文件夹**：例如 `下载目录/葬送的芙莉莲/…`。文件夹名中的字幕组和括号标签会去掉，例如 `[Group] 作品 [01-12][1080p]` 识别为「作品」。
3. **下载目录根部的散落文件**：按文件名中解析出的作品名分组。

季度按以下优先级确定：`Season 2`、`S02`、`第二季` 这类季度文件夹，其次文件名里的 `S2`、`S02E05`、`第二季`、`2nd Season`，再次作品文件夹名，最后是订阅设置的季度。同一作品文件夹下的不同季度分开显示。

`SPs`、`Specials`、`OVA`、`Season 00` 文件夹中的视频算作特别篇；`CDs`、`Scans`、`NC`、`Menus`、`Extras` 等文件夹中的视频，以及 NCOP、NCED、PV、CM、Menu，算作花絮。

扫描会跳过：仍在下载的文件（旁边有 aria2 的 `.aria2` 控制文件）、隐藏文件、符号链接，以及 `@eaDir`、`#recycle`、`$RECYCLE.BIN` 等系统目录。最多索引 50000 个视频文件。

## 集数识别

| 命名方式 | 示例 |
| --- | --- |
| 字幕组常见格式 | `[LoliHouse] 葬送的芙莉莲 - 05 [WebRip 1080p].mkv`、`- 05v2`、`- 12.5` |
| 全括号格式 | `[Nekomoe kissaten][Sousou no Frieren][05][1080p].mp4`、`【喵萌奶茶屋】★10月新番★[作品][05]` |
| 欧美 / 压制组 | `Frieren.S01E05.1080p.WEB-DL.mkv`、`EP05`、`#05` |
| 中文 | `第05话`、`第十二話`、`第5集` |
| 特别篇 / 花絮 | `[SP01]`、`- OVA`、`[NCOP1]`、`[Menu]` |

年份（如 `[2024]`）、分辨率和编码标签不会被误认为集数。名称中「/」或「 - 」分隔的多个译名都会用于搜索，中日文名优先。

目前不使用 AI 兜底识别：对已有大量文件的目录首次扫描时，会产生大量 AI 请求。计划在海报墙阶段，作为单个作品的手动操作提供。

## 资料来源

每个作品按以下顺序确定对应的条目：

1. 手动指定的 Bangumi 或 TMDB 条目（`POST /api/library/{id}/match`）。
2. 订阅上已记录的 Bangumi 条目（订阅的 `bgmId`）。
3. 订阅对应 Mikan 番剧页上的「Bangumi番组计划链接」。订阅的 Mikan ID 取自 RSS 地址中的 `bangumiId`；从「发现番剧」订阅时也会直接记录。
4. 用作品名搜索 Bangumi。只接受名称或别名与作品名相互包含的结果，避免模糊搜索返回无关作品；按季度挑选续作。续作的名称里常常没有发布名使用的写法（例如繁体名只出现在第一季的别名中），只要和匹配上的第一季同名、季度一致，也会选中续作。
5. 已填写 TMDB API Key 时搜索 TMDB 剧集。

通过 Mikan 链接或手动确定的 Bangumi 条目会写回订阅，之后的文件夹与界面直接使用。修改订阅的 Mikan 番剧后，自动匹配结果会重新计算，手动匹配不受影响。

没找到条目或请求失败时，分别在 1 小时、6 小时、1 天后重试；手动「重新获取」立即重试。分集标题先按季内集数匹配，再按总集数匹配，兼容字幕组续季接着上一季编号的写法。

海报使用 Bangumi 的 800px 封面或 TMDB 的 w500 海报，下载时校验文件头，只保存 JPEG、PNG、WebP 和 GIF（不接受可携带脚本的 SVG），单张上限 10 MB。所有请求都经过「网络代理地址」。Bangumi 请求带有本项目的 User-Agent，符合其 API 使用要求。资料来自 [Bangumi 番组计划](https://bgm.tv) 和 [TMDB](https://www.themoviedb.org)。

## 数据存放

| 位置 | 内容 |
| --- | --- |
| `数据目录/library/library.json` | 媒体库索引，与 `state.json` 分开保存 |
| `数据目录/library/posters/` | 海报缓存，文件名为作品 ID；作品消失后自动删除 |

索引可以通过扫描重建。文件损坏时会另存为 `library.json.<时间>.corrupt` 并重新建立，同时在活动记录中提示；这种情况下只有手动匹配会丢失。订阅备份不包含媒体库。

更改下载目录后，作品按相对路径识别，目录结构不变时已获取的资料会保留。

## 接口

均需登录；写操作需要 `X-Aria2Fast: 1` 请求头。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/library` | 状态与作品列表（标题、季度、海报地址、集数、匹配状态等） |
| GET | `/api/library/status` | 作品数、视频数、各匹配状态数量、上次扫描时间 |
| POST | `/api/library/scan` | 立即扫描并返回状态；新作品的资料在后台获取 |
| GET | `/api/library/{id}` | 作品详情、Bangumi / TMDB 资料与分集（含分集标题） |
| GET | `/api/library/{id}/poster` | 海报图片；地址带版本号，浏览器可缓存 7 天 |
| POST | `/api/library/{id}/match` | `{"bgmId": 400602}` 或 `{"tmdbId": 209867}` 手动匹配；两者都为空时恢复自动匹配 |
| POST | `/api/library/{id}/refresh` | 重新获取资料 |

作品状态 `status` 为 `Pending`（待获取）、`Matched`（已匹配）、`Unmatched`（未找到）、`Failed`（获取失败，`error` 中有原因）；`matchedBy` 为 `Manual`、`Subscription`、`Mikan` 或 `Search`。

## 限制

- 只扫描本地节点的下载目录。远程节点的文件 Web 服务读不到；以后会支持把远程目录挂载到本机后做路径映射。
- 订阅目录在下载目录之外时不会被扫描。浏览器取回文件同样只限下载目录内的文件。
- 不写入 NFO，也不改文件名，因此不影响做种，也不会与 Jellyfin / Emby 的整理冲突。
